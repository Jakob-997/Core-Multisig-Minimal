PRE-CREATION GUIDE

Before creating the wallet, confirm all of the following:

[ ] I have verified the Tails ISO.
[ ] I am working in non-persistent storage in the normal Tails session, not Persistent Storage or another writable disk.
[ ] I am using Bitcoin Core v32.0rc2 and have verified the release and the release-signing key fingerprints I trust.
[ ] The CoreVault folder is next to bitcoin-32.0rc2-x86_64-linux-gnu.tar.gz in the same parent folder (any folder works); the tarball is still compressed.
[ ] I have physically air-gapped this computer by removing its network card(s) and will never connect it to a network again.
[ ] I have N + 1 blank CD-Rs with me and they are already labeled for each signer and the watch-only wallet.
[ ] I have protective cases ready for the finished discs.
[ ] I have a fully synced, unpruned Bitcoin Core node on an online computer ready for the test.
[ ] I have a small amount of bitcoin ready to use for the disposable test spend.
[ ] I understand that anyone who gets access to any of these CDs can derive this wallet's addresses and monitor its past and future on-chain activity. A signer CD also contains that signer's private key.
[ ] I have enough uninterrupted time to create the wallet, burn and verify every disc, perform a test spend, shut the computer down, and take every disc directly to its storage location without leaving the computer or backups unattended.

When every item above is true and you are ready to create the wallet, close this
window and return to the Console.

You can reopen these instructions at any time from this project folder:
PRE-CREATION-GUIDE.txt

After wallet creation, the remaining instructions are in:
POST-CREATION-GUIDE.txt

VERIFY YOUR SOFTWARE

Use a verified Tails ISO and Bitcoin Core v32.0rc2.

Official Tails download and verification:
https://tails.net/install/download/

Official Bitcoin Core verification instructions:
https://bitcoincore.org/en/download/#verify-your-download

Official Bitcoin Core v32.0 release-candidate directory:
https://bitcoincore.org/bin/bitcoin-core-32.0/

This project currently requires Bitcoin Core v32.0rc2. Bitcoin Core v31.x and
older will not work. The generator uses the new addhdkey and derivehdkey wallet
RPCs, which are available in v32.0rc2 but not in v31.0.

Until another v32 release candidate or the final v32.0 release has been tested
with this project, use v32.0rc2 exactly.

Verify Bitcoin Core's release signatures, and independently verify the fingerprints
of the release-signing keys you choose to trust. Do not rely only on keys or
fingerprints obtained from the same download you are verifying.

PLACE THE TARBALL NEXT TO COREVAULT

Download the official Linux x86_64 archive from:
https://bitcoincore.org/bin/bitcoin-core-32.0/test.rc2/

Place the CoreVault folder next to the unextracted archive in the same parent
folder. Any parent folder works: Home, Downloads, or another folder. The
launcher finds the archive next to its own folder, wherever you launch it from.
For example:

Downloads/
    bitcoin-32.0rc2-x86_64-linux-gnu.tar.gz
    CoreVault/
        tails.sh
        multisig.py
        PRE-CREATION-GUIDE.txt
        POST-CREATION-GUIDE.txt

Do not extract the archive yourself. The launcher verifies the adjacent tarball
against this hardcoded official SHA-256:

0255103718033e6aee15fa944717fc277e047b845bff1e7408af0ea732d8d0c1

Checksum source:
https://bitcoincore.org/bin/bitcoin-core-32.0/test.rc2/SHA256SUMS

After the checksum passes, the launcher creates a brand-new empty directory next
to the archive with a unique name such as:

bitcoin-32.0rc2-corevault.A1B2C3

It extracts the verified Bitcoin Core release into that new directory and uses
only bitcoin-cli and bitcoind from that extraction. Existing extracted Core
folders and Core installations found through PATH are ignored.

Missing, unreadable, wrong, or damaged archives stop the launcher before Core runs.
Verification is offline and does not download a replacement. It supplements
signature verification; you must still trust the reviewed CoreVault files, Tails,
and system utilities.

The freshly extracted Bitcoin Core directory is intentionally left in place after
the run so you may use it afterward. Only Core's temporary runtime state under
/dev/shm is removed. Wallet backups remain in CoreVault/multisig-backups; they are
not deleted by cleanup. For the intended offline Tails workflow, keep CoreVault in
non-persistent storage as required above, because wallet backups are written inside
its folder.

PERMANENT AIR GAP

If this will be a wallet you actually use, prepare the computer as a permanently
air-gapped machine before generating any keys.

Physically remove its network card(s) and other network hardware where practical,
including Wi-Fi/Bluetooth and WWAN/cellular hardware. Disconnect Ethernet and do
not connect this computer to a network again after using it for the wallet.

PREPARE THE COMPLETE BACKUP PROCESS FIRST

Decide your M-N policy before starting. For an M-N wallet you will need N signer
backups plus one watch-only backup.

If you are using CD-Rs, have N + 1 blank discs ready and label them before creating
the wallet. For a 2-3 wallet, for example:

SIGNER 1 OF 3 — PRIVATE
SIGNER 2 OF 3 — PRIVATE
SIGNER 3 OF 3 — PRIVATE
WATCH ONLY — PUBLIC

Have protective cases ready for the finished discs.

PLAN TO COMPLETE EVERYTHING IN ONE SESSION

Do not start unless you have enough uninterrupted time to complete the entire
process:

1. Create the wallet.
2. Burn every signer wallet and the watch-only wallet to its labeled CD-R.
3. Verify every disc and make sure every wallet loads.
4. Confirm all signer wallets and the watch-only wallet derive the same multisig
   receive addresses.
5. Perform a disposable test spend and try signing with every signer.
6. Confirm the intended M-of-N threshold completes the transaction.
7. Immediately shut the computer down and remove the Tails USB.
8. Put the discs in protective cases and take them directly to their intended
   storage locations.

Once wallet creation begins, keep the computer and all backup media attended until
the computer has been powered off and every backup has been placed in its intended
storage location.

The signer wallets are not encrypted. Anyone who obtains a signer backup can copy
that signer's private key.

When you are ready, return to the Console and enter your M-N policy in the requested
format, for example:

2-3
